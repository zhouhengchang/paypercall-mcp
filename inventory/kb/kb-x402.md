# x402 按次付费：上线前必须知道的 8 件事

## 1. facilitator 同时支持 v1 和 v2

`https://x402.org/facilitator/supported` 会返回支持的组合。只要列表里有
`{"x402Version":1,"scheme":"exact","network":"base-sepolia"}` 就可以走 v1。
不要因为在 `/verify` 上吃过一次 500 就断定"只能上 v2"。

## 2. v1 exact-EVM 的付款要素在 payload.authorization 里面

真实结构：

```
{
  "x402Version": 1,
  "scheme": "exact",
  "network": "base-sepolia",
  "payload": {
    "signature": "0x...",
    "authorization": {
      "from": "0x买方",
      "to": "0x卖方",
      "value": "1000",
      "validAfter": "1700000000",
      "validBefore": "1700003600",
      "nonce": "0x..."
    }
  }
}
```

只读 payload 顶层去找 value/to，会把所有真实钱包的付款都判成"缺字段"。

## 3. 怎么判断"格式是否合规"

发一个**结构完整、签名随机**的载荷给 `/verify`：

- 返回 `invalidReason: invalid_exact_evm_signature` 并回带 `payer` 地址 → 格式对了，真钱包能付
- 返回 `invalid_format` / `unexpected_error` → 字段还缺，真钱包也付不了

这是唯一可靠的自测方法，别用"我觉得字段齐了"。

## 4. 本地绝不能"验个格式就放行"

签名有效性、nonce 是否已被消费、余额够不够，只有 facilitator 知道。
本地校验只做三件事：结构完整、收款地址一致、金额不低于报价、有效期未过。

## 5. 顺序：verify → 干活 → settle

先 settle 再干活，业务一旦失败用户付了钱没拿到东西，必然投诉且无法退款（链上交易不可逆）。
正确的是 verify 通过 → 执行业务 → 业务成功 → settle → 返回 txHash。
业务失败就不 settle，让用户拿同一份 payment payload 重试（nonce 还没被消费）。

## 6. nonce 必须落库唯一索引

否则一笔付款可以重放 N 次。表里给 nonce 建 `UNIQUE`，重复插入直接失败。

## 7. facilitator 不可达时返回 503，不要降级免费

宁可短暂不可用，也不能让爬虫或重放流量白嫖算力。

## 8. 测试网和主网的 asset 地址不一样

- base-sepolia USDC：`0x036CbD53842c5426634e7929541eC2318f3dCF7e`
- base 主网 USDC：`0x833589fCD6eDb6E08f4c7C32D4f71b54bdA02913`

换网必须同时改 `network`、`asset`、`extra.name/version`，只改一个会验签失败。
