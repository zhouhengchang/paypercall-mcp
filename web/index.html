三条收款通道，覆盖不同类型的调用方

这是"每次调用都能收到钱"的关键：不同平台能给的东西不一样，通道必须分开设计。

① 预充值钱包 API Key

平台插件只能传 header，不能签链上交易。用户充值到余额，每调用一次扣一次。

② x402 链上按次 无需注册

Agent 客户端没有你的账号，直接带 X-PAYMENT 头付款。 先验签、干活、成功才结算，拿不到 txHash 不算收入。

为什么失败不扣费

上游模型挂了、SKU 不存在、参数不对，这些都不该让客户掏钱。 账上只记成功交付的调用，毛利曲线才可信。

上游不可用返回 503，进失败台账，金额 0
参数不合法返回 400，不触发扣费
余额不足返回 402，同时给出 x402 付款选项
x402 结算失败已交付但记 0 收入 + 真实成本，亏损可见
