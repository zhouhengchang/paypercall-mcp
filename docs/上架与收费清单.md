# 多渠道变现清单：哪些平台真能收到钱

先说结论，避免把时间花在收不到钱的地方：

**能让你"每次调用都收到钱"的只有三类渠道**，其余都是引流位。

| 类型 | 收钱方式 | 代表平台 | 特点 |
|---|---|---|---|
| A. 自有结算 | 你的 API Key + 预充值 / 订阅 | MCP 市场、npm、GitHub、Gitee、魔搭、各类工具站 | 钱直接进你账户，无分成，你控价 |
| B. 平台内结算 | 平台交易组件（虚拟支付/席位/付费 Bot） | 微信小程序(Android)、抖音小程序、支付宝小程序、钉钉应用市场、扣子 | 需企业资质，平台抽成，规则变动风险高 |
| C. 协议级按次付费 | x402 链上结算 | x402 生态目录、支持 x402 的 Agent 客户端 | 无需注册，按次到账，但要自己实现中介 |
| D. 只能引流 | 无 | 开放平台类（微信/抖音/B站/快手/高德/地图）、云厂商市场 | 上架不等于能收钱，只做曝光入口 |

> 下表 "⚠需核实" 的条目是你清单里较新的平台/市场。它们的规则变动快，
> 我不会编造"它们支持付费"这种结论。请用文末的**三问判断法**逐个确认，
> 确认一个再投入一个。

|---|---|---|---|

### C 类：x402 协议目录（无需注册，按次到账）

| 平台 | 能否直接收钱 | 说明 |
|---|---|---|
| x402 生态（facilitator + 目录） | 是 | 最贴合"每次调用都收钱"。你在网关里已实现 v1 exact-EVM |
| 各 Agent 客户端（支持 x402 的） | 是 | 客户端自动付款，无需账号 |
| Metera / Agensi / SkillExchange / MCPlug / Qellaris / XPack / Spark / 腾讯 TokenHub / 美团 DeepSkill Market | ⚠需核实 | 多为新兴目录或内部市场。**先确认是否托管收款**，见三问判断法 |

### D 类：只能引流（别指望收钱）

| 平台 | 现实定位 |
|---|---|
| B 站 / 快手 开放平台 | 内容分发入口，导流到自有落地页 |
| 高德 / 百度地图开放平台 | 开发者能力，个人无法直接售卖 |
| 腾讯云 / 阿里云 / 火山引擎 / 华为云市场 | 需企业资质 + 上架审核，个人优先用"云函数部署自己服务" |
| CloudBase | 用来托管你的网关，不是收入来源 |
| 字节小程序平台 | 与抖音小程序同源，按抖音规则走 |
| GitHub / npm 之外的模型平台（DeepSeek/GLM/星火/百川/MiniMax/Kimi/百炼/千帆/混元/OpenRouter） | 这些是**你的成本项**，不是收入项。它们是上游供应商，你要做的是压价与路由 |

> 这一行很关键：把 16 个模型平台当"渠道"是常见误区。它们是成本，
> 网关里的 `config/providers.json` 就是用来做**成本路由**的——同一个请求
> 优先走最便宜的可用模型，毛利就是这么来的。

## 二、三问判断法（对任何新平台都适用）

上架前问三个问题，任一答"否"就不要投入开发：

1. **这个平台有没有托管收款？** 也就是用户的钱能不能在平台内付给你。
   如果只能放外链，那它就是引流位，不是收入渠道。
2. **能不能拿到调用方的身份？** 拿不到身份就无法计量、无法限额、无法对账，
   也就无法按次收费。
3. **平台协议允许"把用户导流到你自有服务"吗？** 很多平台明令禁止站外交易。
   允许的才做转化闭环，不允许的只做品牌曝光。

三个都"是"→ 投入。两个"是"→ 只做轻量上架。一个"否"→ 放弃或只做 SEO 占位。

## 四、定价纪律

1. **单价必须高于上游成本 1.5 倍以上**。低于这个数，一次失败的退款或一笔客服成本就吃掉利润。
2. **按次固定价，不要按 token 浮动计价**。x402 要求报价必须在调用前确定，
   事后按实际用量补差在链上做不到。
3. **用 max_tokens 封顶控成本**，而不是靠信任上游不超发。
4. **调价只看后台的"毛利率"列**，不看感觉。`/admin` 里每个工具的毛利率是实时的。
5. **新客先用免费工具建立信任**：`pricing.list` → `policy.check` → 再买付费。

## 五、风控红线（违了就是下架封号）

- 不站外引导交易（微信/抖音/支付宝等平台的硬规则）
- 不二次分发用户输入数据
- 不承诺极限词与功效（网关已内置 `policy.check` 帮你扫）
- AI 生成内容按规定标识
- 商用素材必须有可举证授权链（`asset.license.issue` 的签名凭证就是证据）
- 上游模型 API 的转售要看清各厂商条款：部分厂商禁止"以 API 形式转售"，
  这类只能做成"应用功能"卖，不能做成"裸 API 卖"

> 最后这条最容易踩。DeepSeek/通义等部分厂商条款限制裸转售，
> 稳妥做法是**包装成具体应用能力**（如"面试题生成""合规预检"），
> 而不是"卖 token"。网关里的工具命名已经按这个思路设计。

## 五之二、收款码合规（已接进 `/#topup`）

| 码 | 类型 | 能用吗 | 风险与做法 |
|---|---|---|---|
| 微信 `Mr周恒昌 经营` | **经营收款码**（带"经营"标识，商户主体） | ✅ 可以 | 可用于经营性收款。单笔限额按商户等级，需在商户后台看账单核对 |
| 支付宝（个人码） | **个人收款码** | ⚠️ 不建议长期用 | 央行 259 号文明确个人静态码不得用于经营性收款；易被限额、无法开票、无交易凭证。建议换**商家收款码**或签「当面付」 |
| 当面付 / 微信商户 API | 商户接口 | ✅ 首选 | 有异步回调，可**自动入账**，无需人工核对。签下来后接 `/webhook/alipay`、`/webhook/wechatpay` |

**三条必须知道的现实约束：**

1. **收款码没有回调**。个人/经营码不会通知服务器"有人付了钱"，所以网关里这
   两条通道是**人工核对**（提交 → 后台比对账单 → 点开通）。凡是说"扫码秒到账
   自动开通"的，要么接了商户 API，要么在骗人。
2. **必须比对账单再点开通**。客户可能填错交易号，也可能拿别人的图来报。
   后台「待核对充值」里有金额、渠道、交易号、联系方式四项，对上了再点。
3. **收款码会公开在公网页面**。实名信息（商户名"周恒昌"）会随码一起公开，
   这是收款码的固有属性。介意就把码换成商户简称，或改为"提交后人工发码"。

**升级路径（按收益排序）：**
- 先跑收款码收款（0 门槛，今天就能收）
- 月流水过万后签**当面付/微信商户**，接回调自动入账，省掉人工核对
- 有营业执照再上小程序虚拟支付（Android 可内购，iOS 走实物/服务类目）

## 六、30 天上架顺序建议

**第 1 周（0 成本，立刻能收钱）**
1. 网关部署到有公网 IP 的机器（云函数/轻量服务器均可）
2. 发 npm 包 + GitHub 仓库，README 挂充值入口
3. 提交 MCP 目录（Smithery 等），配置 `smithery.yaml` 里的 apiKey

**第 2 周（要资质，先排队）**
4. 微信小程序（只做 Android 虚拟支付）+ 支付宝小程序
5. 钉钉应用市场（企业认证最慢，先提交）
6. 扣子：插件上架（免费引流）+ Bot 付费侧收费

**第 3 周（内容侧引流）**
7. B 站/小红书发"我自己做了个按次计费的 MCP"实操内容，导流落地页
8. 知识星球/小报童开专栏，成员送 API 额度

**第 4 周（高客单）**
9. 程序员客栈/Upwork 接定制单，用 `custom.quote` 做漏斗
10. 复盘后台毛利表，砍掉毛利 <30% 的工具，把流量挪给高毛利 SKU
